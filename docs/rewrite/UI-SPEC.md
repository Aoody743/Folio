# Folio 面板制作文档与设计规范

版本：0.1 · 更新：2026-10-13（Asia/Singapore）· 状态：制作规范，尚未实现界面。

## 1. 产品方向

面板用于快速获取主机状态、找到资源、完成管理操作和交接信息。AI 通过原生 MCP 访问同一数据与动作；面板内不内置聊天、模型选择器、模型运行时或 AI 助手侧栏。

首页提供人和 AI 都可以读写的共享便签。人的操作与 MCP 操作共用权限、任务、审计与版本规则，界面展示谁修改了什么以及操作的真实结果。

视觉方向：简洁、有层次的卡片；克制的圆角、边框与阴影；固定底部导航；多套配色。依据用户草图保留“上方两张主要信息卡、下方两张次要信息卡、最下方一条导航”的关系。

现有全部功能仍在迁移范围。精简通过信息分层和导航实现，不删除网站、数据库、软件、终端、防火墙或其他插件能力。

## 2. 信息架构与底部导航

底栏固定五个一级入口，各入口包含图标和中文标签；当前入口有背景和颜色状态，不能只靠图标颜色识别。

| 一级入口 | 内容 | 二级组织 |
| --- | --- | --- |
| 概览 | 主机摘要、共享便签、最近任务、待处理事件 | 卡片详情与完整列表 |
| 网站 | 站点、域名、代理、重定向、TLS、日志、网站备份 | 列表 → 资源详情 → 配置分组 |
| 软件 | 软件和插件、数据库、容器、运行时 | 全部 / 已安装 / 数据库 / 容器 / 运行环境 / 其他插件 |
| 文件 | 文件列表、编辑、上传下载、回收站 | 路径导航和文件操作 |
| 更多 | 监控、终端、计划任务、安全、备份存储、设置、MCP接入、操作记录 | 分类网格 + 搜索 |

数据库在软件中有直接分类入口，其备份、权限、主从同步等放在数据库详情。Docker、云盘、邮件、LDAP等通过软件分类和全局搜索直接访问。首屏可精简，但每个功能要有明确入口与返回路径。

全局搜索支持页面、资源名称、软件和操作记录；它是导航/查找功能，不把输入当作自然语言自动执行命令。搜索选中一个动作时进入相应操作页面。

底栏不设置 AI 聊天按钮。MCP 配置和客户端权限位于“更多 → MCP 接入”；便签作者可以显示 AI 客户端身份。

## 3. 首页布局

桌面布局示意：

```text
Folio          当前主机 · 在线                  搜索  任务

┌──────────────────────────┬──────────────────────────┐
│ 主机总览                 │ 共享便签                 │
│ 主机信息 / 服务健康       │ 置顶便签与最近修改       │
│ CPU / 内存 / 磁盘         │ 最后编辑者 / 时间        │
│ 数值与简短趋势           │ 新建 / 查看全部          │
└──────────────────────────┴──────────────────────────┘

┌──────────────────────────┬──────────────────────────┐
│ 最近任务                 │ 待处理事件               │
│ 安装 / 备份 / 升级        │ 失败任务 / 证书 / 容量    │
│ 状态 / 进度 / 查看详情    │ 严重度 / 简短原因 / 入口  │
└──────────────────────────┴──────────────────────────┘

        ╭─────────────────────────────────────╮
        │ 概览    网站    软件    文件    更多 │
        ╰─────────────────────────────────────╯
```

### 3.1 页面框架

- 内容最大宽度 1200px，居中；桌面外侧留白 24–32px。
- 页头只放品牌、当前主机、连接状态、搜索和任务入口；页标题 24px，不放大面积欢迎语或装饰。
- 主内容使用 12 列网格。桌面首行两张卡各占 6 列，次行同样各占 6 列；间距 20px。
- 首行卡片内容区域约 300–360px；次行约 180–220px。内容变多时进入详情，不无限拉高首页卡片。
- 页面底部至少预留 112px 与 safe-area 空间，底栏不遮挡内容、表单或操作按钮。
- 底栏桌面最大宽度 640px，高度 64px，距视口底部 20px；5 个入口均匀分布。窄屏遵循响应式规则。

### 3.2 主机总览

首要信息是在线/离线、主机名称、服务异常；随后展示 CPU、内存和磁盘。指标必须带单位和统计范围。

每项指标包含名称、当前值及短进度条/趋势。默认不铺开大量实时曲线；点击进入完整监控。CPU、内存等主机用量不能标成“面板自身用量”。

卡片显示最近数据更新时间。数据断开后保留最近快照，并明确标记失联/过期；不能继续显示“全部正常”。

### 3.3 共享便签

首屏展示最多 3 条，置顶优先，其余按更新时间排序；显示标题、两行正文预览、最后编辑者和相对时间。固定有“新建”和“查看全部”入口。

便签是首页主要信息卡，不缩成难以发现的角落组件。为空时显示“记录待办或交接信息，人和已授权的 AI 都可编辑”，并给出新建入口。

### 3.4 最近任务

默认展示最近 3 条，进行中的任务优先；提供任务类型、目标、状态、进度与详情。人的操作和 MCP 操作均出现在这里，来源用短标签区分。

提交成功、执行成功、验证成功是不同状态。任务失败显示具体原因及详情入口；不能以绿色“已提交”替代最终成功。

### 3.5 待处理事件

只展示需要用户处理的异常或近期提醒，例如证书到期、任务失败、存储容量。每条有时间、来源、原因和资源入口。

没有事件时显示简短正常状态，不虚构警告或为了填满卡片重复指标。提示颜色与业务严重度绑定，不跟随主题变成任意颜色。

## 4. 共享便签交互与协作

### 4.1 数据与展示

| 字段 | 规则 |
| --- | --- |
| 标题 | 最多 80 个 Unicode 字符；首页单行截断，可展开 |
| 正文 | 最多 10,000 个 Unicode 字符，同时设置 64KiB UTF-8 请求上限 |
| 内容格式 | 简单 Markdown：段落、列表、待办、链接、内联代码；禁用原始HTML |
| 置顶 | 人与获授权AI均可修改，明确权限 |
| 关联资源 | 可关联主机/网站/服务等；打开便签能跳到资源 |
| 作者与来源 | 服务端身份写入，区分人、MCP客户端；正文不能伪造作者 |
| 更新信息 | revision、时间、最后编辑者；每次成功修改形成新版本 |
| 归属 | 默认当前主机；面板级便签明确标识，读取与编辑遵循资源范围 |

作者标签使用“人 · 用户名”或“AI · 客户端名”，说明来源，不显示“AI已理解”或“AI正在思考”。MCP服务可用不等于有AI在线，界面不能据此伪造客户端状态。

### 4.2 创建、读取与编辑

1. 点击便签，桌面打开详情抽屉，保留首页上下文；手机进入全屏详情。
2. 阅读状态显示正文、关联资源、作者和时间；编辑通过明确按钮进入。
3. 编辑包含标题、正文、Markdown预览和置顶，支持取消和完成。
4. 编辑过程中 800ms 停止输入后自动保存，显示“正在保存 / 已保存 / 保存失败”；完成操作应等待待提交修改保存成功。
5. 无网或保存失败时保留当前草稿，提供重试；不得关闭后静默丢失内容。
6. 草稿只做本地临时状态；MCP与网页共同读写的是服务器中的便签，不把localStorage当共享数据库。

勾选便签中的待办只修改便签内容。网站部署、数据库备份等实际系统操作通过正式界面或MCP动作执行；便签正文不触发自动执行。

### 4.3 并发修改与历史

- 客户端读取 revision/ETag，保存携带 expected_revision/If-Match。
- 人与AI同时修改时，服务端拒绝过期版本写入；REST返回412，MCP返回结构化冲突结果并提供当前revision。
- 未在编辑的便签收到更新时刷新预览，并标明最后编辑者；正在编辑时保留草稿，显示“内容已有新版本”。
- 冲突提供“查看最新并合并”和“保存为新便签”；不默认覆盖，也不自动将两份内容简单拼接。
- 历史提供版本、时间、身份及差异；恢复旧内容创建一个新版本，保留过程记录。
- 归档与永久删除分别处理；归档可恢复，永久删除使用明确操作与相应权限。
- “已读”如实现，必须关联具体版本与明确的读取确认，不能把AI读接口成功称为完成了便签中的任务。

### 4.4 MCP 映射

新增计划工具：`notes_list`、`notes_get`、`notes_create`、`notes_update`、`notes_archive`、`notes_restore`、`notes_delete`、`notes_history`；读取资源为 `folio://notes/{id}`。永久删除使用独立权限。

输入带资源范围与版本约束，输出为结构化便签和revision；作者从MCP认证身份生成。提供read/write/archive等可配置权限，授权范围内直接执行，不要求每次编辑都去网页确认。

更新通过网页的SSE状态通道通知，MCP客户端依据支持情况使用资源更新通知或再次读取。分页、预览和限量正文避免一次把所有便签送进AI上下文。

## 5. 视觉规范

### 5.1 卡片

- 卡片圆角 20px，边框 1px，内边距 24px；窄屏内边距 16px。
- 卡片标题、指标、正文、次要信息层次清楚；一张卡只承担一个主要主题。
- 使用低对比边框和轻阴影形成悬浮感，可有极淡的背景渐变；避免粗白描边、大面积发光和霓虹字。
- 数值对齐、留白与网格承担主要视觉效果，不增加持续动画、粒子背景和旋转装饰。
- 交互目标有真实hover/focus状态；普通信息卡不假装整个区域都可点击。

### 5.2 间距与字号

| 用途 | 规范 |
| --- | --- |
| 基础间距 | 4px单位；常用8/12/16/20/24/32px |
| 页面标题 | 24px / 32px，600 |
| 卡片标题 | 16px / 24px，600 |
| 主要指标 | 28px / 36px，600，数字tabular-nums |
| 正文与控件 | 14px / 22px |
| 辅助信息 | 12px / 18px；不再压小 |
| 正文字体 | 系统sans-serif，覆盖中文与拉丁字符 |
| 命令/代码 | 系统monospace，按需加载编辑器字体 |

默认不依赖外部字体CDN。若引入品牌字体，打包本地资源并测量首屏成本。

### 5.3 组件

以Astryx为基础，统一Theme、按钮、表单、表格、弹窗、导航和反馈。Folio定义语义token，再映射至Astryx主题和业务CSS模块。

- 主按钮一个操作区最多一个；其他用次级/文字按钮。
- 图标统一风格、常用尺寸18/20px；底栏图标与文字共同出现。
- 可触达目标至少44×44px；输入与按钮高度默认40px，触屏布局至少44px。
- 状态统一：正常、处理中、提醒、失败、离线；同时给出文字和图标。
- 列表默认显示关键列，其余进入详情；文件和大量日志列表使用分页/虚拟化。
- 配置编辑在提交前显示变更摘要；操作结果就近呈现，toast只作补充。

## 6. 多配色规范

第一版提供五套完整主题，主题改变背景、表面、文字和强调色；业务状态语义保持一致。默认“月白”，尊重用户已保存的选择。

| 主题 | 页面背景 | 卡片表面 | 边框 | 主文字 | 次要文字 | 强调色 |
| --- | --- | --- | --- | --- | --- | --- |
| 月白 · 浅色 | #F5F7FB | #FFFFFF | #DDE3EC | #182230 | #596579 | #2859D6 |
| 深空 · 深色 | #10141B | #181E28 | #2A3443 | #EDF2FA | #A7B3C5 | #88ADFF |
| 雾紫 · 浅色 | #F6F3FB | #FFFEFF | #E4DEEF | #27213A | #6B607E | #6F48B8 |
| 松绿 · 深色 | #0F1916 | #172620 | #294237 | #E9F3EC | #A8BEAF | #8ECCA8 |
| 暖砂 · 浅色 | #F8F5EF | #FFFDF8 | #E9E1D4 | #352A22 | #756558 | #9C5526 |

语义token至少包括background、surface、surface-raised、border、text-primary、text-secondary、accent、on-accent、success、warning、danger、focus-ring、shadow。深色主题主按钮的on-accent使用深色文字，不能统一套白字。

主题选择位于“更多 → 设置 → 外观”，显示真实卡片/按钮预览和名称；键盘可选，点击立即预览，跨页面一致。可保存为当前用户偏好，启动时避免闪现错误主题；个人外观不由AI便签编辑改变。

允许“跟随系统”使用月白/深空自动匹配；选择明确主题后停止系统自动覆盖。暂不开放任意自定义色，以免破坏基础可读性；后续可加带对比度校验的自定义主题。

本轮已计算上述主文字、次要文字、强调色在相应纯色卡片表面上的对比度，最低为5.50:1。它只验证这些基础色对，实际disabled状态、半透明表面、按钮与focus状态仍需实现后验证。

## 7. 响应式与无障碍

| 宽度 | 布局 |
| --- | --- |
| ≥1024px | 两列卡片，居中底栏，24–32px外侧留白 |
| 768–1023px | 可保留两列，16–20px留白，减少卡片次要信息 |
| <768px | 单列，按主机→便签→任务→事件排列；底栏占满可用宽度 |

手机底栏高度64px加safe-area，入口文字12px，保持至少44px目标。编辑便签使用全屏详情；虚拟键盘出现时收起/避让底栏，输入和保存状态不被遮挡。

所有页面支持键盘导航和可见focus。弹窗/抽屉管理焦点，关闭后回到触发控件；Escape关闭未提交浮层时保留草稿。可提供Cmd/Ctrl+K打开搜索，输入框内不抢占普通字符键。

正常正文对比度≥4.5:1；大型文字与必要非文字控件≥3:1。状态不能仅靠颜色表达，图表有文字数值替代；更新提示可被辅助技术读取且避免频繁打断。

动效默认120–180ms，主要用于状态过渡与抽屉；支持prefers-reduced-motion，避免持续动画。移动端不依赖hover揭示关键操作。

## 8. 状态与文案

- 文案使用动作和对象：“新建便签”“备份数据库”“查看失败原因”；避免技术协议细节占据常规页面。
- 加载保持布局稳定，用骨架/局部占位；空状态有明确下一步，错误状态有原因与重试。
- 时间遵循用户时区；相对时间可查看完整时间。界面不能把服务器时区当用户时区。
- 模拟原型必须标注演示数据；真实界面只展示实际连接、任务和事件。
- MCP接入页面展示接入方式、授权范围、客户端身份、最近访问和操作记录；不提供模型对话或API Key向导。

## 9. 技术制作约束

技术栈沿用Next.js、React 19、TypeScript、Astryx，优先静态导出；Go负责API、认证、任务、MCP与事件通知。

页面和组件按Shell、BottomNav、StatusCard、NotesCard、TasksCard、EventsCard、NoteDetail、ThemePicker、ResourceList等职责组织。生产实现从Astryx真实组件API核查开始，避免根据名称猜组件属性。

便签数据使用SQLite持久化，并有版本/历史/归档记录；共享动作注册表同时提供REST与MCP。主题偏好与便签数据分离。设计中不能用浏览器本地数据冒充跨人/AI协作。

网站/软件/文件详情使用静态页面加客户端数据，避免运行时未知ID依赖Next静态导出不支持的路由行为。编辑器、终端、图表按页面延迟加载。

## 10. 制作顺序与验收

整体开发按 [三阶段开发计划](DEVELOPMENT-PLAN.md) 推进；本节是UI内部制作顺序，不增加独立阶段。

1. 依据本规范制作静态布局：四张首页卡与五项底栏，五套主题。
2. 接入真实组件交互：导航、搜索、详情抽屉、便签编辑和主题保存。
3. 实现共享便签REST/MCP、更新通知、版本冲突和历史。
4. 接入真实主机/任务/事件数据及全部功能导航。
5. 验证桌面、手机、键盘、配色、空/错/断线状态和共享编辑。

验收至少覆盖：

- 首页一眼可区分主机状态、便签、任务和事件；底栏不遮挡内容。
- 全部旧功能存在明确导航/搜索入口；精简页面没有导致范围丢失。
- 五个主题跨页面一致，基本文字与控件状态符合对比度要求。
- 人编辑便签后AI可以读取；AI修改后网页更新，作者与版本真实。
- 并发修改不会静默覆盖，断线/失败不丢草稿，恢复历史可追溯。
- 无内置聊天、模型选择器、虚构AI在线/理解状态或大面积装饰。
- 主页不依赖开启大模型或安装全部受管软件才能工作。

本轮仅交付规范；没有生成运行中的UI原型或实际完成上述验收。
