# 可选浏览器应用

Folio 提供两个独立的可选模式，默认都不安装。入口为 **软件 → 应用服务 → 浏览器应用**；可安装任意一个、同时安装两个，也可以都不安装。安装后的浏览器还会出现在“更多 → 运维”。两种模式均通过服务器 DNS 和网络出口访问网页；服务器使用 NAT、代理或 VPN 时，网站看到的是该出口地址。

| 模式 | 运行位置 | 客户端要求 | 安装行为 |
| --- | --- | --- | --- |
| 面板浏览器 | 服务器 Chromium，面板显示画面与控制 | 常用桌面及手机浏览器，无 JSPI 要求 | 优先复用系统 Chromium/Chrome；Linux amd64 没有引擎时下载独立 Chrome headless shell |
| Firefox WASM | 访问者设备运行完整 Firefox/Gecko，认证 Wisp 在服务器转发网络 | HTTPS（或本机回环测试地址）、JSPI；实测 Chromium 154 | 按需下载约 55 MB 上游发行，校验固定 SHA-256；独立窗口保留完整 Firefox 控件 |

## 安装、权限与卸载

- 安装和卸载为持久化任务，可从应用卡片查看结果和日志；重复提交与版本冲突受到校验。网络或依赖失败时允许检查后重试，不把失败显示为已安装。
- 安装管理同时要求 `software:manage` 和 `browser:use`，资源为 `browser:server`。打开及使用要求 `browser:use`；这是主动使用服务器网络的权限，Wisp 包含 TCP/UDP 转发，应按实际需要授权。
- 两个模式的下载组件都保存在面板私有数据目录的 `browser-apps/`。不向系统安装包目录写文件，不默认启动代理，不开启公共监听或 DevTools 端口。
- 卸载关闭该模式的全部连接，移除面板下载的组件，保留另一模式和系统浏览器。面板模式的临时服务端配置随会话关闭清理。
- Firefox WASM 配置保存在当前客户端浏览器的 OPFS 中，按登录身份隔离。卸载服务器组件不会清除各设备上的本机配置；需要清除时可在客户端浏览器中清理此站点的数据。
- Linux arm64 的面板模式要求先安装发行版提供的 Chromium。本轮没有为 arm64 自动下载可执行引擎；Firefox WASM 不依赖服务器的 CPU 架构，但不因此宣称新增 ARM 主机运行验收。
- 独立 Chromium 下载约 125 MB，启动仍需要系统共享库和可用的用户命名空间沙箱；安装会实际试启动，失败任务提供检查网络、磁盘、系统库与沙箱的说明。不会通过关闭沙箱绕过失败。

## Firefox WASM

使用 [Puter Firefox WASM](https://github.com/HeyPuter/firefox-wasm) `v0.0.1`，而非把普通 Firefox 网站嵌入 iframe。启动前检测 HTTPS/安全上下文和 JSPI，不满足时显示下一步提示，并保留返回应用的入口。完整 Firefox UI 在独立窗口中运行，Folio 的返回与全屏栏为原生标签页、地址栏预留空间。面板的中英切换适用于应用和启动交接；上游 Firefox 控件采用其自带语言，网站内容不翻译。

默认关闭上游实验性 JS→WASM JIT。首次初始化会下载、解压引擎与界面资源，运行消耗客户端内存，适合有足够内存的较新设备；手机优先选择面板模式。支持上游原生地址栏、标签页、键盘和剪贴板粘贴；中文粘贴已通过真实网站验证。

上游默认公共代理和外部字体请求已移除。Wisp 地址固定为本面板的同源端点，客户端配置不能切换到公共 Wisp。请求需要面板登录、同源检查和 CSRF 子协议；转发过程中复核当前身份，撤销授权、卸载或服务关闭会断开连接。每个身份最多一个 Wisp 连接，默认全局最多四个，每个连接最多 32 个流；缓冲和报文长度有限制。

Firefox 页面单独设置 COOP/COEP 和执行 WASM 所需的 CSP；不放宽普通面板页面的 CSP。默认面板包不捆绑大型 Firefox/Chromium 下载。

上游源代码、许可和 Folio 的修改位置见 [第三方说明](../third-party/browser-apps/README.md)。

## 面板模式的操作与限制

先在 **软件 → 应用服务 → 浏览器应用** 安装“面板浏览器”，再从 **更多 → 运维 → 服务器浏览器** 打开。启动后，网页由服务器上的 Chromium/Chrome 打开，面板显示实时画面并传递点击、滚动和键盘输入。客户端浏览器不直接请求目标网站，也不通过 iframe 加载网站。

访问使用服务器的 DNS 和网络出口；服务器本身已有代理、VPN 或 NAT 时，目标网站看到的是该出口地址。此功能不提供新的代理线路。

### 使用

- 点击启动，在地址栏输入 HTTP/HTTPS 地址，或输入关键词搜索。
- 使用标签页、前进、后退、刷新与停止控制网页；点击画面后可以使用键盘。使用“适应窗口”调整远端网页尺寸，全屏后也会适配可用空间。
- 网页提示、确认及文字询问会在画面上方显示，等待明确回复；新窗口链接在当前受控标签页打开。
- 手机或中文输入可通过文本发送框输入到网页当前获得焦点的字段；发送前先点击目标字段。
- 面板语言和主题可以继续切换；访问地址、输入内容和页面 Cookie 不存入面板 URL 或浏览器偏好。
- 关闭浏览器会结束远程进程并清理临时资料。短暂离开模块可以继续会话；闲置会话自动回收。服务器重启后需重新启动浏览器。

本版本用于交互访问网页，不提供远程文件上传、下载管理、音频或摄像头转发。网页声音、视频和动画的体验受截图传输频率及服务器资源影响。

### 服务器环境

需要 Linux 服务器已安装 Chromium 或 Google Chrome，且 Folio 服务用户可以在沙箱中启动它。面板会检查浏览器环境；没有可用引擎时会提示安装后重试。Folio 发行包不捆绑浏览器引擎，不会在后台自动安装系统软件。

请通过系统发行版或浏览器厂商的受信任来源安装。Debian 可使用系统的 `chromium` 软件包；Ubuntu 的 `chromium-browser` 可能是 Snap 启动器，部署前需确认它可由 systemd 中的 Folio 用户启动，或使用厂商提供的 Chrome Linux 软件包。Chromium 自身的系统依赖由对应软件包管理器维护。

生产安装器以 `powerlinux` 普通用户运行面板，保留现有 systemd 限制。浏览器不以 root 启动，不关闭沙箱，不忽略 HTTPS 证书错误，也不对外暴露 DevTools 调试端口。浏览器启动失败时应检查安装、用户命名空间及系统策略，界面会提供可查看的错误信息。

### 权限与接口

浏览器需要独立的 `browser:use` 权限与 `browser:server` 资源授权。此权限允许使用服务器可达的公网和内网网站，应授予允许使用这些网络能力的身份。管理员的完整权限包含该能力。会话按发起身份隔离，不能凭猜测会话标识读取其他身份的画面或输入。

动作通过现有 REST/MCP/Core 注册：环境状态、创建/关闭会话、列出/创建/关闭标签页、导航、历史、输入和调整视口。Cookie 写请求使用现有 CSRF 保护。截图只通过经过身份与权限检查的面板资源接口读取，并禁止缓存；DevTools 使用私有进程管道。

普通面板导航控制不使用持久化幂等响应缓存，也不自动重放不确定的输入。外部 REST/MCP 调用者若显式给返回会话信息的动作附加幂等键，仍遵循既有 Core 缓存语义，响应中的地址、标题可能保留在面板私有数据库中；不要将此功能视为保证抹除所有外部调用记录的匿名浏览器。

只允许 HTTP/HTTPS 网页和空白页，禁止 `file:`、`javascript:` 等地址作为导航目标。网页文本和访问地址不作为审计摘要保存。具体会话预算、租期及接口字段见源码公开的 capability schema；验收证据记录在当前 beta 的发行资产中。
