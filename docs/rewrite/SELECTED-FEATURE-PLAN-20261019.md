# phpMyAdmin/pgAdmin、ACME/DNS 与应用入口适配计划

更新时间：2026-10-19。本计划只覆盖 phpMyAdmin、pgAdmin、ACME/DNS，以及托管应用的 Git、Node.js、Go 入口。它是后续适配与验收计划，不把现有未验收代码改记为完成，也不恢复 MongoDB、FTP 或其他暂缓插件的工作。

## 当前基线

- 首轮真实系统验收目标沿用 Debian 13 amd64 与 Ubuntu 24.04 amd64。其他发行版和架构须有各自的原生证据，不能从 manifest 声明推定已支持。
- `phpmyadmin`、`pgadmin` 已有软件目录条目，但生命周期能力未验收。phpMyAdmin 的签名仓库包尚未完成来源与功能验收，旧版本没有可用的可信来源；pgAdmin 还没有配置可信的软件来源。两者不得通过旧 `install.sh` 执行安装。
- ACME 已有订单、手工 HTTP 验证和 DNS 适配代码。Cloudflare/DNSPod 等 Lego 驱动及 DNSPod International、ISPConfig、Knot、Zilore、Online 原生驱动都需要按供应商逐项验收；代码可用不等于真实签发、清理和续期已通过。FreeDNS、Cyon、KingHost 等标记不可用的适配器继续保持不可选。
- 托管应用当前位于“软件 → 应用”入口，支持 Next.js 和 Go 模板、归档导入、公开 HTTPS Git 导入及固定 SSH 主机指纹导入。它还没有通用 Node.js 项目类型；私有仓库认证未接入；Git、Node.js 和 Go 的软件目录声明均未完成目标系统生命周期验收。

## 目标入口与边界

| 用户任务 | 入口与依赖 | 默认安全边界 |
| --- | --- | --- |
| 创建 Node.js 或 Go 应用 | “软件 → 应用”；源码可选 Git 或归档；Node.js/Go/Git 从“软件 → 软件目录”安装 | 每个应用使用独立非特权账户和 systemd 服务，应用只监听回环地址，由受管网站反向代理；构建和部署进入可审计任务 |
| 管理 MySQL | “软件 → 数据库管理工具 → phpMyAdmin”；依赖受管 PHP-FPM 与 MySQL 兼容实例 | 不新增公网监听端口；通过已有受管站点和 HTTPS 发布，沿用 phpMyAdmin 自身认证，不把数据库密码写进 URL、日志或普通配置回显 |
| 管理 PostgreSQL | “软件 → 数据库管理工具 → pgAdmin”；首批连接受管 PostgreSQL 实例 | 以隔离服务用户运行，监听回环地址，经受管站点和 HTTPS 反代；服务器定义与凭据按敏感数据保存 |
| 签发和续期证书 | “网站 → 证书”；HTTP-01 或已验收 DNS-01；DNS 凭据按提供商配置档案管理 | DNS 凭据加密保存、只在授权动作中使用；TXT 记录按订单精确归属和清理；任务与日志脱敏 |

本轮不加入自动部署 Webhook、任意插件导入、其他语言运行时或未列入范围的旧插件。Node.js 的第一版应支持有 `package.json` 和锁文件的 npm 项目；Next.js 保留便捷模板。Go 项目要求 `go.mod`/`go.sum`，通过 Go 构建并运行生成的程序。

## 分批实施

### 第 0 批：冻结契约和支持矩阵

1. 对照当前 REST/MCP actions、catalog manifest、前端入口和旧插件动作，分别列出 phpMyAdmin、pgAdmin、ACME/DNS、Git、Node.js、Go 的“已实现、待实现、待原生验收”项。
2. 锁定首轮 OS/架构、可信安装来源、可安装版本、运行依赖、配置/数据目录、端口和服务归属。只将 Debian 13 amd64、Ubuntu 24.04 amd64 作为首批验收目标；未验收组合在目录中显示不可用或未验证。
3. 所有长操作复用现有任务、资源锁、权限和审计机制；网页与 MCP 若同时暴露同一动作，必须调用同一业务能力并得到一致授权结果。

**退出条件：** 每个目录条目有可审查的来源、依赖和状态；清单能明确区分代码声明、源码测试、隔离协议测试和目标系统实测。

### 第 1 批：闭合 Git、Node.js、Go 应用入口

1. 在两种目标系统验证 Git/OpenSSH、Node.js/npm 和 Go 的签名包来源、版本、重复安装、状态与卸载行为；清单记录实际版本，不以 `distribution` 占位版本作为支持承诺。
2. 将用户入口明确为 Node.js 与 Go。Node.js 项目要求根目录 `package.json` 和 npm 锁文件，使用锁文件安装依赖并运行项目声明的 build/start script；Next.js 继续使用模板和健康检查。Go 项目校验 `go.mod`/`go.sum`，在受控网络和资源预算下构建，再启动生成的二进制。
3. Git 导入保留公开 HTTPS 与 SSH 固定主机指纹校验；增加私有仓库时使用每应用、可撤销的部署凭据，不接受含口令/token 的仓库 URL。导入后记录仓库、分支/引用和精确 commit，日志不得包含凭据。
4. clone、依赖安装和构建始终以应用专属非特权用户运行，限制时长、输出和并发；部署成功后才切换运行版本，失败保留上一个可用版本。重启后服务、站点反代、日志和状态仍可恢复。

**验收：** 在每个目标 OS 上分别完成公开 HTTPS Git、固定主机指纹 SSH、归档、Node.js 和 Go 的创建/部署/更新/失败恢复/重启/删除；验证未知 SSH 指纹拒绝、错误 lockfile/go.sum、恶意仓库路径和权限越界均不会执行 root 操作。私有 Git 凭据未完成前，界面明确标注不支持。

### 第 2 批：托管 phpMyAdmin 与 pgAdmin

1. 为 phpMyAdmin 和 pgAdmin 配置经过签名校验的官方/发行版来源，并确认目标 OS 上的包名、依赖、升级路径和维护状态。逐项审核来源前不启用安装按钮；不恢复旧版本号但没有可信安装物的选项。
2. phpMyAdmin 接入受管 PHP-FPM 和 MySQL 兼容实例；验证必要 PHP 扩展、配置生成、默认认证方式、访问日志、错误日志、状态和升级。pgAdmin 接入受管 PostgreSQL；验证运行模式、数据目录、server definitions、凭据保存、日志和升级。
3. 两个工具都作为软件目录中的数据库 Web 管理工具安装，并绑定到已有受管网站/域名。默认无公网直连端口；HTTP 头、子路径/独立域名、HTTPS、反向代理和登录行为按实际包版本逐项测试。发布前要求 HTTPS 和访问控制策略，不能只靠随机 URL 保护管理界面。
4. 安装、重配、升级、停止、启动和卸载走持久任务及独立权限；卸载默认保留用户配置/数据，清理前展示范围并单独确认。连接信息及密码只在需要时写入密钥存储，不返回到普通读取响应。

**验收：** Debian 13 与 Ubuntu 24.04 上各完成一次可信来源冷安装和升级；phpMyAdmin 实际读写受权限限制的 MySQL canary，pgAdmin 实际连接 PostgreSQL canary；验证错误登录拒绝、HTTPS 反代、服务重启恢复、日志脱敏、备份/保留数据和卸载行为。不能把 UI 展示、mock API 或成功安装单独作为通过证据。

### 第 3 批：完成 ACME 与 DNS 凭据/挑战闭环

1. 从当前 DNS provider registry 生成支持矩阵：逐项写出提供商、凭据字段、授权最小范围、运行方式、当前 availability 和证据。已标记 unavailable 的 provider 不出现在可执行列表；没有外部验证的 provider 不标成已支持。
2. 统一 DNS 凭据档案的创建、更新、轮换、删除和测试。密文使用现有主密钥机制保存；读取只返回字段是否已配置，不返回密文；错误消息、任务输出和审计记录全部脱敏。ISPConfig 等自定义 API 必须校验 HTTPS 和允许的网络目标。
3. 复用并验收现有 DNS-01 持久订单和精确 TXT 归属机制，按提供商补齐边界：等待传播、向 CA 完成挑战、删除本订单拥有的记录、取消/过期清理。并发订单、响应超时、面板重启、凭据轮换和重试不能删除其他订单或用户创建的 TXT。
4. 对 HTTP-01 与 DNS-01 分别测试申请、续期、失败恢复、取消、证书绑定和服务 reload。提供商先用测试账户/隔离 zone 对照协议测试，再以受控域名和公开 CA 做真实签发及续期；实际供应商账户与域名只留在 QA 环境，不写入仓库。

**验收：** 每个标记可用的 DNS 提供商都要有真实 API 记录创建/查询/精确清理证据；ACME staging 通过后再做受控公开 CA canary。重启后订单继续或安全失败，续期不会覆盖有效证书，DNS/CA 错误可读且无秘密泄露。未取得真实 provider/CA 前提的适配器保持 `not verified`，不能计入支持矩阵。

### 第 4 批：联合回归与支持声明

- 在 Debian 13 amd64、Ubuntu 24.04 amd64 的干净主机上，按固定版本包跑完三批验收；每项证据关联源码 commit、发行包哈希、OS、软件版本和结果。
- 对应用与证书操作检查允许/拒绝/撤权、排队/运行/失败/取消、重启恢复、审计字段和日志脱敏。跨资源操作需验证并发锁和失败回滚。
- 更新 catalog 状态、用户入口文案、安装/运维说明和已知限制；只有完成实测的 OS/架构、版本、DNS provider 和操作才标为可用。

## 依赖与顺序

```text
可信软件来源与平台矩阵
  ├─ Git + Node.js/Go → 应用托管与站点反代
  ├─ PHP-FPM + MySQL → phpMyAdmin
  ├─ PostgreSQL → pgAdmin
  └─ DNS 凭据 + ACME 订单 → 证书签发/续期 → 管理工具公网发布
```

建议先完成第 0 批，再闭合 Git/Node.js/Go 的现有托管链；随后完成两个数据库 Web 工具；ACME/DNS 与其间可并行开发，但任何公网管理工具发布都要等 HTTPS 和访问策略通过。第 4 批是对外标注支持的唯一闸门。

## 交付判断

每批只在代码、目标系统实测和恢复路径都有证据后关闭。当前记录中的 manifest、入口组件、单元/隔离协议测试只作为起点；未验收的版本、DNS provider、OS/架构继续显示未验证或不可用。以上计划不改变当前发行版已验收范围，也不把未完成项追认为已发布能力。
